# PS-PodCast

A collection of PowerShell automation projects for Windows infrastructure administration, organised as six numbered modules. Each module covers one common sysadmin task: Active Directory management, server inventory, patch management, security auditing and configuration compliance.

> **Note:** This README is based on the project's folder and file listing (names, sizes, timestamps). Script behaviour described below is inferred from file names and output artifacts, so adjust it where the scripts do something different.

## Modules

### 01 - Active-Directory
Scripts for the Active Directory lifecycle, meant to be run in numbered order.

| File | Purpose |
|------|---------|
| `Input/DC-Promo.txt` | Notes or parameters for promoting a server to a domain controller |
| `Input/groupList.txt` | List of groups to create |
| `Input/users.csv` | User records for bulk creation |
| `Scripts/1. OU-Groups Creation.ps1` | Creates the OU structure and security groups |
| `Scripts/2. Bulk User Creation Script.ps1` | Creates users in bulk from `users.csv` |
| `Scripts/3. Employee Offboarding.ps1` | Handles departing employees (disable and clean up accounts) |

### 02 - Server Inventory
Collects details from a list of servers and produces reports.

- **Input:** `servers.csv`, the list of target servers.
- **Script:** `4. Inventory.ps1`, which gathers the inventory data.
- **Output:** `ServerInventory.csv` (raw data) and `customOutput.html` (formatted report).

### 03 - Web
Shared web assets. `styles.css` is the stylesheet for the HTML reports generated by the other modules.

### 04 - Patch-Compliance
- `Patch-Management.ps1` manages patching and runs pre-patch checks.
- `Logs/` holds timestamped `PrePatchReport_<yyyyMMdd_HHmmss>.csv` files, one per run.

### 05 - Security-Automation
- `Security-Audit.ps1` runs security audits across the servers in `Config/servers.csv`.
- `SecurityAudit/` contains the results:
  - `LocalAdminAudit.csv`: local administrator membership audit
  - `SecurityEventAudit.csv`: security event log audit
  - `SecurityAudit.html`: combined HTML report
  - `Logs/SecurityAudit.log`: execution log

### 06 - Configure-Compliance
- `Configuration-Compliance.ps1` is the largest script. It checks servers in `Config/servers.csv` against configuration standards.
- Each run writes three timestamped outputs under `Reports/`:
  - an HTML report
  - a CSV export in `CSV/`
  - a run log in `Logs/`

## Conventions

- **Numbered folders** (`01`-`06`) show the intended order and grouping of the modules.
- **Input / Config:** files that drive the scripts (`servers.csv`, `users.csv`, etc.). The same `servers.csv` appears in modules 02, 05 and 06, so keep copies in sync or point the scripts at one shared file.
- **Output / Reports:** generated results, usually as CSV and HTML.
- **Logs:** timestamped logs from each run, named `<Name>_<yyyyMMdd>-<HHmmss>`.

## Prerequisites

- Windows PowerShell 5.1 or later
- Active Directory module (RSAT) for module 01
- Administrative rights on the target servers, plus remoting (WinRM) access for modules 02 and 04-06

## Usage

1. Clone or copy the repository and open PowerShell as Administrator.
2. Edit the relevant input files (`users.csv`, `servers.csv`, etc.).
3. Run the script for the module you need, for example:

```powershell
cd ".\02-Server Inventory\Scripts"
.\"4. Inventory.ps1"
```

4. Review the generated reports and logs in the module's output folders.

## Notes

- Review each script and test in a lab before running against production systems, especially the user creation, offboarding and patching scripts.
- Generated reports, logs and input files containing real server or user data should not be committed to a public repository. Consider adding them to `.gitignore`.
